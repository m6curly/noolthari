# NOOLTHARI V2.1 — storefront refinement

## Visual and mobile updates
- Replaced mixed text/emoji header symbols with one consistent outline SVG set for Search, Wishlist, Bag, Account and Menu.
- Kept existing page filenames, relative asset folders, Supabase client paths and Vercel project metadata.
- Removed the duplicate Account control shown to signed-in users.
- Made the mobile navigation available at tablet widths and improved its expanded/collapsed accessibility labels.
- Refined header/footer typography, spacing, surfaces and link hierarchy.
- Added touch-friendly control sizing, iOS input sizing and safe-area padding.
- Removed Colour and Occasion filter dropdowns from The Collection, while preserving those product data fields and search indexing.
- Refined responsive Collection filter layout and invalid price-range feedback.
- Replaced the product wishlist text heart with the same outlined SVG icon family.

## Paths and integration values
- Existing route/page names and relative assets are retained.
- `js/config.js`, `js/supabase.js`, `.vercel/project.json`, and the four original payment Edge Function source files are unchanged from the uploaded ZIP.
- Supabase source is included under `supabase/`; see `SUPABASE-UPDATE-GUIDE.md`.
- The V2.1 visual updates require no new SQL migration.

## Checks performed
- `npm run check`: passed (32 HTML pages, 32 JavaScript files, local references, duplicate IDs, JSON configuration and secret-pattern checks).
- CSS parser: no stylesheet syntax errors.
- HTML structural checks: no empty/unlabelled header icon links; four header utility links on all 19 pages with a storefront header.
- Browser simulation at widths 320, 360, 390, 430, 620, 700, 768, 860, 861, 900, 960, 1000, 1001, 1024, 1100, 1101, 1200 and 1440px: no horizontal overflow; menu open/close state verified.
- Mocked shop interaction checks: dynamic category/fabric options, search/category filtering, invalid price range focus/message and Clear Filters reset.
- Mocked wishlist interaction checks: insert and delete state transitions.

## Not certified by local checks
Live Supabase policies/migrations, authenticated customer/admin sessions, real Razorpay capture/refund/webhook events, transactional email delivery and physical Android/iPhone hardware were not available for production end-to-end testing. These must be checked on a staging project/device before production deployment.
